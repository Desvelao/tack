## [0.2.0] - 2026-10-19

- BREAKING: the project is renamed from `tkan` to `tack`: the binary, the Go module, `tack.yaml` / `.tack.yaml`, the `.tack.nextid` sidecar and the release assets (`tack-*`). Rename your config and sidecar files; the repository moves to `Desvelao/tack`.
- Fix: `tack add` reports an invalid `-due` before an invalid `-start` every time; it used to pick one at random when both were wrong.
- Fix: the interactive `interactive_timeout` timer of an action is released when the command ends instead of living on.
- Docs: `<file>.nextid` should travel with the backlog (commit it); only `*.lock` belongs in `.gitignore`. The quoting rules of the filter language and the events `tack watch` fires are written down.
- Chore: the CSV backend runs on `filestore.Store` with a codec; CI actions are pinned to commit SHAs and the publish job re-verifies `SHA256SUMS`; the Dockerfile pins the Go image by digest and builds as a non-root user; more tests for claims, `Merge`, the query tokenizer and the hook runner's limits.
- Test: `proc.KillLeftovers` is covered (a wrapper's background child is killed, the grace-period kill is cancelled) and the reason it cannot hit a recycled process group is written down next to it.
- Fix: a hook with `dedupe: true` removes its marker when the event is dropped here (already running, queue full, superseded, cancelled), so another process can still run it instead of the event being lost for ten minutes.
- Fix: a CSV with `\r\n` line breaks inside quoted cells (as Excel writes them) keeps them on write instead of turning them into `\n`.
- Fix: when the overlay file cannot be written, an edit that also changed the wrapped store is undone there (best effort) instead of leaving half of it behind.
- Fix: the overlay retries pruning stale entries after a transient error (lock timeout, a failed read of the store); only a permission or read-only error switches it off.
- Fix: the `yaml` backend keeps per-task comments, quoting and key order on every write: unchanged tasks are written back as they were and an edited task only has its changed values replaced. Tasks that are anchors or use aliases / `<<` are still rewritten flat (documented). Unquoted dates in the file stay unquoted.
- Fix: `make release` starts from an empty `bin/` and checksums exactly the binaries and backend scripts it built, so leftover files (renamed assets, old `tkan-*` names) are no longer hashed or published.
- Fix: `install.sh` copies the binary or backend script next to its destination and renames it into place, so an interrupted run or a busy binary never leaves a truncated file; a downloaded binary that does not run gives a clear error.
- Fix: `install.sh` stops on Ctrl-C or `kill` (exit 130 / 143) after removing its temp dir; it used to carry on against the deleted directory.
- Fix: ordering terms (`<`, `>`, `<=`, `>=`) expand `today`, `tomorrow` and friends only on date fields, like `=` and `!=`; `title>today` compares the text.
- Fix: relative dates (`today`, `tomorrow`, `today+7d`) are expanded for `:`, `!:` and `^` on date fields too, so `due:today` matches and `due!:today` no longer matches everything; a malformed one (`due:today+7`) is an error there as well.
- Fix: `field!~regex` and `field!^prefix` (and `!<`, `!>`) are now filter errors; they used to become a plain-text term that matched nothing.
- Fix: a `board.columns` name that is also another column's value (column `Review` with values `[qa]` plus a column named `qa`) is rejected at config load; `set-status qa` used to write a different value than the cards showed.
- Fix: `board.avatars` keys that differ only by case (`Bot` and `bot`) are rejected at config load; they used to pick a random picture per frame.
- Fix: `tack release` clears a leftover `lease` or `claimed_at` on a task with no assignee without `-force`, instead of failing with "not claimed by".
- Fix: `edit -if FIELD=VALUE -append-notes` (and MCP `edit_task` with `if` + `append_notes`) no longer loses a note appended by another writer at the same time: the append is guarded on the notes and retried on the fresh task, with `-if` re-checked on each retry (exit 4 when it no longer holds).
- Feat: `workdir` (actions, hooks, the `custom` backend option, `tack run -workdir` and the picker's `w`) expands `$VAR`, `${VAR}` and a leading `~`, next to absolute paths. A variable that is not set is an error instead of an empty string. The environment is expanded before `{id}` / `{slug}`, so task text is never expanded.
- Feat: `tack run ACTION ID... -workdir DIR` and `w` in the `x` picker run an action in another working directory for that run (relative: to the current directory for `-workdir`, to the config's directory in the picker; `.` repeats the picker's choice). `w` is now reserved by the picker, so an action `key: w` is rejected.
- BREAKING: `cwd` is now `workdir` and `create_cwd` is `create_workdir` (actions and hooks, and the `custom` backend's `cwd` option); `tack actions -json` / `tack schema` and new action-log records say `workdir`. Rename the keys in `tack.yaml`; records already in the log keep their old `cwd` and show an empty workdir.
- Feat: `tack actions -json` and `tack schema` list each action's `cwd` (as configured, placeholders unfilled) when it has one.
- Feat: `create_cwd: true` on an action (or hook) creates its `cwd` (with parents) when it does not exist, so a templated `cwd` such as `/work/{slug}` works without a `mkdir` in the command. It needs `cwd`.
- Fix: `jsonl` files starting with a UTF-8 BOM no longer fail with `line 1: invalid character`, and `json`, `jsonl` and `yaml` write the BOM back instead of silently dropping it on the first write, like csv.
- Fix: `q` and `ctrl+c` no longer drop a background write that is still saving: `q` says "still saving" and waits, the first `ctrl+c` warns and a second one quits anyway.
- Docs: the `.lock` sidecar is no longer called Unix-only (`LockFileEx` on Windows, never run there), and the `.lock` / `.nextid` sidecars and their `.gitignore` advice are noted for `json`, `jsonl` and `yaml` too.
- Fix: `install.sh -h` printed a usage without the `-s` line and printed nothing when piped (`curl ... | sh -s -- -h`, where `$0` is `sh`); the usage text is now a `usage()` function in the script.
- Fix: with an `overlay:` on the claim fields, a claim or release that also changes the status (`release -status S`, `next -claim -to S`, `claim -status`) no longer fails with a spurious precondition error: the overlay checks the guard on the overlaid field itself and no longer passes it to the wrapped store.
- Fix: agent names are matched ignoring case in `claim`, `release`, `next -claim` and `run` (claim: true), like the workers view: a task held by `claude` can be renewed or released as `Claude`, and a renewal keeps the stored spelling.
- Fix: `tack run -i` (or `mode: interactive`) failing before the command starts (e.g. `stdin: json`, a missing cwd) now leaves a record, audit entry, end hook and `on_failure` outcome, like the background path; it used to leave `action.started` unanswered.
- Test: the filestore has a multi-writer test (separate stores on one file, no lost write; runs under `make race`) and a `WriteAtomic` mode test, and CI runs the filestore tests and vet on Windows, where the lock was only compile-checked.
- Feat: `on_success` / `on_failure` take a `command` (a list, placeholders plus `{result}` and `{exit}`) next to or instead of the move: `on_success: {status: Review, command: [notify-send, "{title} is ready"]}`. A failing command only prints a warning.
- Feat: `task.moved` now also fires for a status change made outside this process (source `poll`, `{old_status}` set), and the new `task.changed` fires when any other field than the title changed (`{old_json}` holds the previous version; lease renewals are ignored). Both come from the same reload diff as `task.appeared`, so they see the state at each reload: several changes between two reloads arrive as one event, and a backend that loaded only in part is skipped. A title edit still reads as a reused ID (`task.disappeared` + `task.appeared`). `dedupe` stays limited to `appeared` / `disappeared`.
- Feat: `tack watch [-q QUERY] [-interval 2s] [-json]` runs the poll events without the board: `task.appeared`, `task.disappeared`, `task.moved`/`entered`/`left`, `task.due`, `column.wip_exceeded`, `reload.ok` and `reload.fail` fire from a server or an agent host, with source `watch`. `-q` narrows what is watched, `-json` also prints each event as one JSON line (the `stdin: event` shape). It runs until interrupted (exit 130). Next to an open board, set `dedupe: true` on the hook so only one of them runs it. The diff state moved out of the TUI into `hook.Watcher`, which both use.
- Feat: `overlay:` on a `backend:` entry keeps chosen task fields in a local JSON file instead of the store: `overlay: claims` (assignee, lease, claimed_at) or `{file, fields}`. Claims (`claim`, `next -claim`, `release`, `claim: true`, the workers view) then work on a store that cannot hold them or that you may not write to, such as a shared GitHub Project; guarded claims stay atomic between processes sharing the file. Overlaid values are marked `⌂` on cards, in the detail and workers views and in `show`/`workers` text; `-json` gets `"overlaid": [...]`. New `overlaid` field on the task JSON.
- Change: the workers view (`W`, `tack workers`) shows only agent work: an assignee listed in `board.agents` or holding a lease. A plain assignee such as a person is no longer listed, and the `held` state is gone (states: `busy`, `expired`, `idle`).
- Feat: the installer can fetch the backend scripts: `install.sh -b sqlite` (or `-b all`, `$TACK_BACKENDS`) installs `tack-sqlite.sh` to `~/.local/share/tack/backends` (`-B DIR` / `$TACK_BACKEND_DIR`), `-s` skips the binary. The scripts are release assets listed in `SHA256SUMS` (`make release` adds them), everything is verified before anything is installed. `make install-backends` copies them from a clone. README and `docs/backends.md` explain the installer, manual download and `cp` routes; `contrib/install-test.sh` (`make test-install`, part of `make check`) tests the installer against a fake release.
- Feat: SQLite is provided as the script `contrib/backends/sqlite/tack-sqlite.sh` (bash, jq and `sqlite3`) for the `custom` backend: configurable column mapping (`TACK_SQLITE_FIELDS`), extra columns kept, atomic claims and writes of only the changed columns; `tack init -backend sqlite` writes its entry. `make test-contrib` tests it.
- Feat: the `custom` backend implements `backend.Patcher`: an `update` also carries `base` (the task as the caller read it), so a command that writes only the differing fields keeps another writer's change to a different field. Commands that ignore `base` replace the whole record as before.
- Feat: a `backend:` entry with `command: [./tool.sh]` is a `custom` backend, no `type` needed (`type: custom` with `options.command` is equivalent, but not both). `tack init -backend custom` writes it.
- Feat: the `custom` protocol supports atomic claims. Every request carries `"version":1`; an `update` made under a guard (`claim`, `release`, `next`, `run -claim`, `set-status -from`, `edit -if`) carries `"expect":{"field","value"}` and the command answers `"code":"precondition"` (exit code 4) when it no longer holds. A `list` answer with `"guard":true` makes tack skip its non-atomic read-and-check; `"fields":[...]` says which logical fields the store keeps.
- Feat(tui): `m` then a column number (`1`-`9`) moves the selected card, or all the marked cards, to that column; `u` undoes the move in one step.
- Feat(tui): `d` deletes all the marked cards at once (one `y/N`); `u` restores them in one step.
- Feat(tui): the `#ID` of a task is bold amber on cards and in the detail view.
- Feat(tui): every role has its own colour. The header tags (loading, failed backend, marked, finished, sort, group, filter) no longer share one orange, errors and `⟳ running` use the red and cyan styles, the card meta colours labels and the backend, the workers and detail views use the card colours, and keys in the help are highlighted. The palette (`tui/palette.go`) has ANSI-16 fallbacks and light/dark variants. Text cues survive `NO_COLOR`: `▸` marks the focused column, the selected card has a thick border, a column over its WIP limit is red. The header line is cut at the terminal width.
- Feat: `disabled: true` on a `backend:` entry keeps it in the config but skips it (validated, not opened; its actions and hooks are ignored). `tack config` still lists it.
- Feat: the board opens at once and lists its backends in the background. The configured columns are drawn empty, the header shows a spinner with the name of each backend still loading (`loading…` in the focused column), and cards appear as each backend answers; a backend that fails is named (`✗ NAME`) and the others stay. `r` and the poll-driven reload also run in the background; keys that write (`n e d u x . H L`) wait with `still loading: NAME`. `custom` backends no longer list while opening in the board (the command is checked by the first background list), and the `board.search/sort/group` field check runs after the first complete load (as a board notice) instead of before the board starts. One-shot commands are unchanged. `bin/ghproject-sandbox/gh-stub.sh` takes `STUB_DELAY` to try it.
- Feat: the result of a run goes back to the task. `on_success` / `on_failure` also take `{status, append_notes}` (`on_fail` is an alias): `append_notes: stdout|summary` (success) or `stdout|summary|error` (failure) adds a capped block to the task's notes, also after a failed run. New `tack edit ID -append-notes TEXT|-` (and `-append-notes-file`, MCP `append_notes`) adds to the notes without rewriting them (cannot be combined with `-notes`).
- Feat: agent discovery. New `tack schema` prints, as JSON, the task fields, every command with its flags (read back from each command's `-h`, so they cannot drift), the exit codes, the filter fields of tasks, audit and runs, the `{placeholders}` and the configured actions. New `tack actions [-json]` lists the configured actions (before, only the hidden `__complete actions`). `delete` takes `-json` (`[{backend,id,title,deleted}]`), so every write command can answer in JSON. `tack mcp` gains `next_task`, `claim_next_task`, `claim_task`, `release_task` and `schema` (the claim ones are write tools; `-read-only` keeps `next_task` and `schema`).
- Feat: `tack mcp [-read-only]` serves list_tasks, get_task, count, statuses, add_task, edit_task, set_status and run_action to AI agents over stdio (Model Context Protocol, hand-written JSON-RPC with the standard library, no new dependency). It is a thin layer over the existing subcommands (same validation, guards and exit codes, reported as `isError` tool results), runs only configured `actions:` (never interactive ones), offers no `delete`, and audits as `source=mcp`; `-read-only` lists and allows only the read tools.
- Feat: machine-readable `tack run` and a way for agents to report back. `run -json` prints a summary per run (`result`, `exit_code`, `duration_ms`, `run_id`, `truncated`, `log`, `error`, `status_before`/`status_after`; one object for one ID, a list for several) and sends the command's own stdout to stderr so stdout stays pure JSON. `run -propagate-exit` exits with the command's own status (1-125) instead of 1 (2/3/4 then collide with tack's codes; timeouts and cancels stay 1/130). The command gets `TACK_RUN_ID` and, with `action_log`, `TACK_ACTION_LOG`; action-log records carry `run_id`. New `tack report ID [-status S] [-note TEXT|-] [-run ID]` moves the task and/or appends a timestamped note tied to `$TACK_RUN_ID` (audit op `report`, action-log record with `source: report`). New action keys `capture: notes` (+`capture_max` KiB, default 4: append the start of stdout to the task's notes), `on_success` and `on_failure` (move the task when the run ends; not when canceled, and not when the task's status changed during the run, so an agent's `report -status` wins), for `tack run` and the board; rejected for hooks.
- Feat: agent workers view: `W` in the board (and `tack workers [-json]`) lists the agents working on tasks, derived from the claims (an assignee that is neither listed in `board.agents` nor holding a lease, e.g. a person, is not shown): avatar, agent, state (`busy`: a lease still running, or an agent listed in `board.agents`; `expired`: the lease ran out; `idle`: a listed agent holding nothing), the task, when the claim started, how long it has run and how much lease is left. It follows other terminals' claims through the board's one-second poll. A busy agent's avatar animates (500 ms): new `board.avatars` (`NAME: [frame, ...]`, emoji or text) overrides the defaults. New optional task field `claimed_at` (RFC 3339 UTC, set by `claim`/`next -claim`/`claim: true`, kept on a renewal, cleared by `release`; csv column, synonyms `claimed`, `claim_start`; `{claimed_at}` placeholder, filter field); a store without the column still works, the start is then unknown. The claim name of an action with `claim: true` now defaults to the action's name (was `tack-run` / `tui`; `-as` and `$TACK_AGENT` still win). Fix: `board.agents` from the config file now reaches the board (it was dropped when the file was loaded). `tack workers -json` is the stable contract for scripts or plugins that draw the workers their own way.
- Feat: a working directory per run: `cwd` and `env` values of actions and hooks take placeholders (in `cwd` only `{id}`, `{backend}` and the new `{slug}`, made path-safe), the environment gets `TACK_WORKDIR`, and `docs/config.md` shows the `git worktree` recipe for one checkout per task.
- Feat: more hook events: `task.entered.COLUMN` / `task.left.COLUMN` (a status change that takes a task to another board column, from a write or seen on a reload), `task.due` (a task not in a finished column is due or overdue; once per task per day) and `column.wip_exceeded` (a column went over its `limit`); the last two fire while the board is open. New hook placeholders `{column}`, `{old_column}`, `{new_status}` (env `TACK_COLUMN`, `TACK_OLD_COLUMN`, `TACK_NEW_STATUS`).
- Feat: hook concurrency: new top-level `hook_max_parallel` (0 = unlimited, max 64) caps the hook runs at once over all hooks (a bulk `set-status 1 2 3 doing` no longer starts one agent per task; events over it follow the hook's `queue`), and a new per-hook `unique: task` skips an event while the hook is still running for the same task (this process only). Events dropped by any hook limit are now audited with `result=skipped` instead of `ok`.
- Feat: inspect and try hooks: `tack hooks [-json]` lists them (name, backend, on, when, timeout, command), `tack hooks test NAME [ID] [-b NAME] [-event E] [-old-status S] [-n]` fires one on a made-up event for a task: `when:` and the depth limit apply (exit `4` when they stop it), `-n` prints the command, its variables (the hook's `env:` values as `***`) and the stdin size, otherwise it runs once (no limits or retries) and is audited and logged like a fired run, with `{source}` = `test`. `tack help events` lists the events. A `when:` on `task.delete.fail` (or `task.delete`) warns at load, since that event often carries only the task id.
- Feat: claiming work for several agents: `tack claim ID... -as AGENT [-lease 30m] [-status S]` writes the agent as `assignee` (and with `-lease` a new optional field `lease`, the RFC 3339 UTC time the claim runs out) in one write guarded inside the backend's lock, so of several agents exactly one wins; the others exit `4` (`claimed by X until T`). A task is claimed while it has an assignee, until its lease if set; an expired lease can be taken over (guarded on the old lease), the holder may re-claim to renew. `tack release ID... [-as AGENT | -force] [-status S]` clears assignee and lease. `tack next [-q|-v|-status] [-claim -as AGENT [-lease D] [-to S]] [-json]` prints the most urgent (priority, then store order) task in an unfinished column that is neither blocked nor claimed, and with `-claim` claims it, moving on to the next candidate when another agent was faster (exit `3` when nothing is left). `-as` defaults to `$TACK_AGENT`. New action key `claim: true`: `tack run` (`-as`, default `$TACK_AGENT` or `tack-run`) and the board (as `$TACK_AGENT` or `tui`) claim the task around the run with a lease of timeout + kill grace and release it afterwards; a task another agent holds starts nothing (exit `4`; a board batch skips it as busy). `lease` is mapped by every backend (csv column, synonyms `lease_until`, `claimed_until`; `{lease}` placeholder, filter field); `claim -lease` on a csv store without that column exits `2` (new optional `backend.FieldStorer`).
- Feat: per-backend actions and hooks: a `backend` entry takes its own `actions:` and `hooks:` (same fields as the top-level lists) for its tasks only. One with the name of a top-level action or hook replaces it for that backend; the `x` picker lists what applies to the card's backend (with marked cards of several backends, the actions all of them have, each card running its own backend's), and `tack run NAME ID...` runs each task's version (exit 2, nothing started, when a task's backend has no such action). A backend's hook fires only on its tasks' events; `reload.*` are rejected there.
- Feat: background run endings are hard to miss: every screen (card details, edit form, help, audit, picker, run output; the board's title line) shows `N finished (R)` until the runs view is opened, and a new opt-in action key `notify: bell|desktop` rings the terminal bell or sends an `OSC 777`/`OSC 9` desktop notification when a background run ends (once per batch; rejected for `interactive` actions and hooks).
- Feat/fix: `task.appeared` / `task.disappeared` are more exact: an own write only hides the change it made (an own update followed by an outside delete in one poll window now fires `task.disappeared`, an own delete followed by an outside re-create fires `task.appeared`), and an ID whose title (or `created` field) changed between two reloads is reported as reused (disappeared + appeared; an outside title edit looks the same). New per-hook `dedupe: true` (only with those two events) runs the hook in one board only, through an `O_EXCL` marker in `.tack-dedupe/` next to the config (pruned after 10 minutes; audit `skipped (duplicate)`); add it to `.gitignore`.
- Feat: run state on the cards: a card with a background action going shows `⟳ NAME 12s` (`+N` when more run on it), then `OK`/`FAIL NAME 3s` for 8 s; the card details list the runs going on it with their elapsed time and the ones that just ended; new filter field `running` (`yes`/`no`, board only: empty in `list`/`count`/`labels`, rejected in a hook's `when:`). Starting an action that is already running on the card warns and needs the same start again within 10 s (an `exclusive` one is refused); a batch on marked cards skips the cards it is already running on and names them in its summary. New `board.agents` (assignee names of AI agents) highlights their cards (border colour, bold `@name`, `agent` in the details). The fields help page shows `id, backend` on one line to stay on one screen.
- Feat: task dependencies: a new optional field `blocked_by` (ids of tasks of the same backend, comma-separated; a list in json/jsonl/yaml, numbers when the file's ids are) is mapped by every backend like the other fields (csv column, `options.fields.blocked_by`, `custom` JSON key; `-blocked-by` on `add`/`edit`, the board's edit form, `{blocked_by}` placeholder). A task is blocked while one of those tasks exists and is not in a finished column (Done, Closed, ...; unknown ids and its own id do not block): the card shows `blocked by #N` in red (the details list all ids), the action picker warns (it still runs), `tack run` refuses a blocked task with exit `4` and starts nothing unless `-force`, and the new filter fields `blocked` / `ready` (`yes`/`no`) work in the board, `list`, `count` and `labels` (not in a hook's `when:`, which is rejected at load). `list -json` adds `blockers`, the ids still open. The fields help page shows `due, start` and `blocked, ready` on one line each to stay on one screen.
- Feat: re-run and multi-select actions in the board: `.` repeats the last action on the selected card (also in the card details, keeping `i`); `space` marks cards (`✓` on the card, `N marked` in the header; marks follow backend and ID through reloads and filters, are dropped when the card disappears, `esc` with no filter clears them) and `x` then runs the chosen background action on every marked card, at most `action_max_parallel` at once (new top-level key, default 2, 1..16), skipping cards gone before their turn, with one summary notice. `tack run ACTION ID...` accepts several IDs: resolved first (unknown = nothing runs, exit 3), run one after another, a failure does not stop the rest (exit 1 at the end).
- Feat: hooks get `retries` (0..10) and `retry_delay` (default 1s) for flaky targets: a failed run (exit status, timeout) starts again with the same event; every attempt is in the action log, the audit trail records the last with `(attempt K of N)`; Ctrl-C/quit stops pending retries. To POST an event to a URL, use `curl` with `stdin: event` (`docs/config.md#posting-to-a-url`): there is no built-in HTTP client, to keep the binary small.
- Docs/feat: how placeholders meet the shell is documented (`docs/config.md`, "Placeholders and the shell"): argv is never shell-parsed, but a placeholder inside an `sh -c` script is shell code; pass values as positional parameters (`[sh, -c, 'echo "$1"', sh, "{title}"]`). `tack run` and, for hooks, every command that loads the config warn about a placeholder inside a `sh|bash|zsh|dash|ash|ksh -c` script.
- Feat: hook runs in the action log carry the firing `event` (new `event` field, filterable: `-q 'source=hook event:task.moved'`); `R` shows `NAME [event]` in the list and the output header, and `tack runs` has an EVENT column (`-` when none).
- Feat: hook rate limits: `max_parallel` (default 1 for hooks that listen only to `reload.*`, so a slow `reload.ok` hook no longer piles up processes; unlimited otherwise), `min_interval` and `queue: drop|latest|all` (all capped at 100); dropped events are audited as `skipped (...)` except `reload.*`; queued events are waited for on exit and discarded on Ctrl-C. No debounce.
- Feat: configurable hook recursion: top-level `hook_max_depth` (default 1 = a `tack` started by a hook fires nothing; hard cap 3, larger values are rejected at load) and an optional per-hook `max_depth`; commands get `TACK_HOOK_CHAIN=a>b` and a hook already in the chain never fires again, so pipelines such as "agent moves a card to Review, which fires the reviewer" work without loops.
- Feat: an action or hook whose command looks like an AI agent (`claude`, `codex`, `aider`, `gemini`, ...; also after `env`) and sets no `timeout:` prints `tack: warning: actions[N] NAME: ...` on stderr when a command opens the config (before the board starts), since it would be ended at the 10s default; `mode: interactive` is exempt and exit codes are unchanged.
- Feat: hook-only `stdin: event` (one JSON line `{event,source,error,action,old,task}`) and `stdin: event-markdown` (event list, then the task as `stdin: markdown`) so an agent learns what happened; actions reject them.
- Fix: task ids are no longer reused after the highest one is deleted: csv, json, jsonl and yaml keep a high-water mark (`<file>.nextid`) written under the same lock, and a new id is `max(max id, mark)+1`; a missing sidecar falls back to `max+1`. Add `*.nextid` to `.gitignore`.
- Fix: change detection no longer misses a same-size edit within the file system clock granularity: the file stamp now includes inode and change time (Unix) and, for small files modified in the last 2 seconds, a content hash, in csv, json, jsonl and yaml.
- Feat: compare-and-set writes: `set-status ... -from STATUS` and `edit ... -if FIELD=VALUE` apply the change only if the task still has that value, checked inside the backend's lock or transaction (csv, json, jsonl, yaml, and `custom` commands that report `"guard":true`), and exit with the new code `4` otherwise (a precondition for claiming a task); other `custom` commands can only re-read just before writing. `backend.WithExpect` / `backend.ErrPrecondition` carry the guard.
- Fix: the runs view reads only the newest 200 stored runs from the action log (older entries are not parsed; the header says how many were left out and `A` loads all), and the output view and the runs list refresh every 250 ms while a run is going instead of waiting for the 1 s tick.
- Feat: actions and hooks get `kill_grace` (SIGTERM, then SIGKILL after the grace, default 5s, `0s` = at once; Unix process groups, ignored on Windows), `max_output` (KiB kept per stream, default 256) and `exclusive` (one background run per card, in-process only); actions also get `interactive_timeout`. `tack run` prints a background action's stdout while it runs. Permission presets are not added (documented in `docs/config.md`).
- Docs/fix: task text in its own argument can still be parsed as an option (`--add-dir /`); `docs/config.md` and `tack.example.yaml` recommend `--` or `stdin: markdown`, and `tack run` warns about an argument starting with `{title}`/`{description}`/`{notes}`/`{labels}`/`{assignee}` that follows a plain argument without `--`.
- Fix: filters match single labels: `labels=ops`, `labels!=ops` and `labels^op` compare the entries of the label list (whole label, case-insensitive), so `labels=ops` finds `ops,wip` but not `devops`; `labels:` still searches the text and `labels=` still means no labels.
- Fix: `set-status` and `delete` with several IDs that fail part-way now say so on stderr (`stopped after moving/deleting N of M tasks`), `set-status -json` prints the tasks already moved and the over-limit warning is still given; the non-atomic behaviour is documented in `docs/usage.md` and `docs/AGENTS.md`.
- Fix: the audit file is created with mode `0600` instead of `0644` (entries hold task titles), and the new `audit.max_size` (KiB) rotates it to `FILE.1` once it is larger, under the append lock, so it no longer grows without bound; `docs/config.md` documents both.
- Fix: the `custom` backend's poller no longer reports tack's own `update`/`create`/`delete` as an outside change (no extra reload); the next poll just refreshes its baseline.
- Docs: `docs/backends.md` says precisely that `Update` never removes an extra key or column (one the caller's copy lacks is kept) while `Patch` removes one the caller dropped relative to its base; a csv test pins both.
- Fix: the `custom` backend's `poll` option is parsed like the other backends': a bare number is seconds (`poll: 5`), `none` disables polling, and `watch` (meaningless without a file) is the same as unset; `docs/config.md` says so.
- Filter help says what each field means, for every filter: the board help has a third page (`?`, `tab` twice) with the task fields, `?` in the filter prompt of the audit and runs views shows their syntax and fields, `tack help filter [audit|runs]` prints them, and `tack audit -h` / `tack runs -h` list the fields of `-q` with their meaning. `docs/filter.md` mirrors the tables.
- The board's undo writes with `source=undo`, so a hook can tell it from a normal move or edit (`{source}`, `TACK_EVENT_SOURCE`).
- Fix: a hook's `when:` can use extra columns / frontmatter keys of the tasks (`customer:acme`); only a typo of a built-in field is rejected at load.
- Fix: `task.appeared` / `task.disappeared` no longer fire once per task when a backend that failed to load comes back (or when the first load was partial): a backend is left out of the comparison while it was incomplete in either list.
- Docs: hook recipes for AI agents (a Claude Code hook on `task.moved`, one on `task.appeared`, fail-back on `action.failed`, Codex/Aider shapes) checked with `tack config`, and a "Running AI agents safely" section (untrusted task text, tool lists, timeouts, loops); `docs/AGENTS.md` tells an agent started by a hook what to do.
- Fix: quitting the board or finishing a command no longer hangs silently while hook commands run: tack says `waiting for N hook run(s)` and Ctrl-C (or an interrupted command) kills them and their children, recording them as errors.
- Fix: two tack processes starting on a new `audit.csv` could each write the header row; CSV appends now take a lock (`audit.csv.lock`, ignored by git). The `race` job also covers the backends.
- Fix: moving or editing a card no longer writes an old copy of the other fields over what an agent or another board changed meanwhile (for example its notes). The board's move and edit, `tack edit` and `tack set-status` now write only the fields they changed (`backend.Patcher`, implemented by csv, json, jsonl, yaml and custom); undo still replaces the whole record.
- Fix: the board footer no longer wraps at 80 columns (the hint drops the least important keys to fit and keeps `? help` and `q quit`), so the top of the board stays on screen with the runs strip, a notice and a prompt; the card view footer lists `x` and `R`.
- Fix: an action that ends while you are typing, editing or confirming a delete no longer reloads the board or replaces the notice under you (they wait until you are back on the board); the delete confirmation deletes the card it asked about, and the undo of a move or edit of a card is dropped when an action ran on it, so `u` cannot put an old copy over the command's changes.
- Fix: what an action prints can no longer corrupt the board: escape sequences are removed, a line a program redrew with `\r` keeps its last version, other control characters are dropped, notices and headers are one line, and every cut is measured in terminal cells (wide CJK/emoji titles no longer overflow the strip, the picker or the runs list). `x/ansi` (already a dependency of the TUI) is now a direct one.
- Fix: the runs view (`R`) and the action picker (`x`) scroll with the selection and show `(a-b of n)`, so with many runs or actions the header and footer stay on an 80x24 screen; `pgup`, `pgdn`, `home` and `end` move faster.
- Fix: `x` is reserved in the action picker (it closes it), so an action with `key: x` is rejected at load instead of silently doing nothing; a test keeps the reserved set and the picker in step.
- Fix: the Windows build failed (`windows.UnLockFileEx` is spelled `UnlockFileEx`).
- Fix: an action whose `cwd` does not exist says so ("working directory ... does not exist") instead of "fork/exec ...: no such file or directory"; a `Cancel` that arrives after a successful exit no longer marks the run canceled.
- `make race` runs the tests of the concurrent packages with the race detector (own image with a C compiler; also in CI).
- Fix: the action log reader (`R`, `tack runs`) no longer stops at a record larger than 8 MiB and silently drops every later run; the stdin kept in a record is capped like the output; action names with accents or other non-ASCII letters get their own folder in `action_log: {dir}`.
- Fix: the audit summary of an action run (`op=run`, hook runs) no longer includes the first line of output or the command's error text, which could carry a token or a prompt into the audit file (readable by anyone); it keeps the action, duration, exit status and output sizes. The details stay in the private `action_log`.
- Fix: a card with very long notes or description no longer makes every action (and hook) fail to start with "argument list too long": an oversized `TACK_TASK_JSON` / `TACK_OLD_TASK_JSON` is left out of the environment (`..._OMITTED` says to use `stdin`), an oversized argument fails the run with a message naming the `{placeholder}`, and NUL bytes in task text are dropped.
- Fix: Ctrl-C, SIGTERM or SIGHUP no longer leave action processes running or unrecorded. `tack run` kills the action with its children, records the run (audit and action log) and exits `130`; the board, however it ends (`q`, signal, error), kills and records its running actions before exiting.
- Fix: action and hook commands may contain braces that are not placeholders (`awk '{print}'`, `${HOME}`, `jq`): only known `{names}` are replaced and a near-miss such as `{titel}` is still rejected with a suggestion. `{{` and `}}` write a literal brace.
- Filter: relative dates also take `m` (months) and `y` (years) (`due<today+1m`), and a malformed one (`today+7`, `today+1x`, or a typo such as `due<tomorow`) is now an error with a suggestion instead of being compared as text.
- Fix: `tack edit` validates the merged task like `add` does (for example a `-start` after the stored due date) and reports it as a usage error (exit 2) instead of a generic failure.
- Fix: when the audit file cannot be written (missing directory, full disk, no permission) the commands print `tack: warning: audit log: ...` on stderr and the board shows the error on its status line, instead of losing the trail silently. The write itself and the exit code are not affected.
- Fix: updates are validated like creates (non-empty title, `due`/`start` as YYYY-MM-DD, start not after due) for every backend, so `tack edit` and custom backends cannot store an empty title or a bad date. A card that already breaks these rules must be fixed before it can be moved again.
- Fix: a json, jsonl or yaml record with two keys that differ only in case (`Title` and `title`) no longer loses one value on the next write: the key spelled exactly like the mapped one is the field, the other stays an extra key.
- Fix: a list or object stored in a mapped field (`title`, `due`, ...) of a json, jsonl or yaml file is written back as a list/object, not as a quoted string, when the task is updated; text typed over it stays a string.
- Hooks: a `hooks:` list in the config runs a command on events, reusing the action command spec (placeholders, `env`, `stdin`, `timeout`) plus `on:` (`task.create|update|delete[.success|.fail]`, `task.moved`, `task.appeared`, `task.disappeared`, `reload.ok|fail`, `action.started|finished|succeeded|failed`) and a `when:` filter in the query language. Placeholders `{event}`, `{source}`, `{error}`, `{old_status}`, `{old_json}`, `{action}` and the matching `TACK_EVENT*` variables. After-events only; a failing hook never fails the write and is audited (`op=hook:EVENT`, e.g. `hook:task.moved`; `op=run` stays for actions); commands carry `TACK_HOOK_DEPTH` so a `tack` they run fires no hooks; one-shot commands wait for them. Internal: `backend.Set.SetHook` reports whole tasks of every write.
- Actions: an `actions:` list in the config defines commands run on a task, for example to hand it to Claude Code or another AI agent, or to send a notification. `x` in the board opens a picker (an optional `key` per action; `i` runs it with the terminal), `tack run ACTION ID [-i] [-n]` runs it from scripts. The command is an argv list (no shell) with `{id}`, `{title}`, ... placeholders, `TACK_TASK_*` environment variables and optional task JSON/Markdown on stdin; `mode: background` (default, `OK`/`FAIL` in the status line, `timeout`) or `interactive` (suspends the board). Runs are audited as `op=run`.
- Background actions are visible: a strip above the status line shows each run with its elapsed time and, for 8 s after it ends, `OK`/`FAIL` with the duration; `R` lists the runs of the session, `enter` shows the output live (stdout, then stderr), `c` cancels a run, and quitting cancels the ones still going. New action option `show: output` opens the output when the run ends. Runs are audited with a one-line summary (`op=run`: action, duration, exit status, output sizes); `tack` never puts the environment in it.
- Optional `action_log:` (off by default; `file: x.jsonl` or `dir: x`, one JSON file per run in a folder per action) stores the details of every action run: command and stdin as run, stdout, stderr, start, duration, exit status; environment values are never stored and files are private. `R` lists earlier sessions' runs from it (command, stdin and output on `enter`, `/` filter) and `tack runs [-q] [-limit] [-json]` prints them.
- Internal: the capped output writer and process-group helpers of the `custom` backend moved to `internal/proc`.
- TUI: writes (move, edit, new, delete, undo) now report `OK` (green, fades after ~4 s) or `FAIL` (bold red, stays until a key) with the backend error, cut to the terminal width; a failed re-read after a write is no longer hidden by the success message.
- Audit trail of reloads (ok/error) and create/update/delete, from the board and the subcommands: `A` in the board, `tack audit`, filterable by `op`, `date`, `details`, `result`, `source`, `backend`, `id`, `session`. In memory by default; `audit.file` (`.jsonl` or `.csv`) keeps it across sessions and marks this and the previous one.
- csv option `poll`: `watch` (default, as before), `none` (read once; `r` reloads) or a number of seconds between checks for outside edits.
- Docs: `AGENTS.md` now requires a security review of staged changes (exposed secrets and other concerns) before every commit.
- Fix: the board did not show external changes to the file (not even with `r`) because the one-shot list cache was also on for the board.
- `json`, `jsonl` and `yaml` backends: tasks in a JSON array (or `{"tasks": [...]}`), a JSON Lines file or a YAML list, with `fields` key mapping, `poll` and `indent`; unmapped keys round-trip through `extra`, with their types. `yaml` is selected with `-backend yaml` (the `.yaml` extension is not claimed).
- `json` and `yaml` option `path`: dotted keys to the task list inside a larger document (`data.tasks`); the rest of the document is kept on writes.
- `tack init` writes a default `source` matching the backend (`tasks.json`, `tasks.yaml`, `tasks/`, ...) when none is given.
- Internal: the lock and atomic-write code of csv moved to `internal/backend/filestore`, shared with the new file backends.
- The `poll` option parser is shared (`backend.ParsePoll`).
